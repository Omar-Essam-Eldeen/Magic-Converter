## Features

### 1 — Recent & favourites
- `history.ts`: localStorage `converter-app:history:v1`, entries exactly `{key, category, target, count, lastUsed, favourite}` with `key = "${category}:${target}"`. Exports `loadHistory`, `recordUse`, `toggleFavourite`, `clearHistory` (keeps favourites), plus `sortedHistory` (favourites → count → recency). Stored data is validated on load.
- `recordUse` fires only on a **successful** conversion (in `convertItem`, after the done patch).
- UI: "Quick convert" card between dropzone and Advanced, rendered only when history is non-empty; top 6 chips. Chip label = localized category + arrow + target (bare upper-cased extension where sensible, e.g. `Image → JPG`; otherwise the localized target label, e.g. `PDF → PNG per page`). Star button with `aria-pressed` + `aria-label`. "Clear" text button clears non-favourites (and disarms if the armed route was cleared).
- Clicking a chip applies its target to all queued **idle/error** items of that category (error items reset to idle, mirroring the target-select behaviour) **and** arms the route one-shot: the next added file of that category (drop/pick/paste/share) gets the target pre-selected, then the arm is consumed. While armed the chip is highlighted and the hint line shows ("Next {cat} file will convert to {target} — drop or pick a file to use it."). Judgment call: tapping the already-armed chip again disarms it (the spec defines no cancel path, and a stuck arm would be worse).

### 2 — Smarter defaults
- Prefs stay on the same key `converter-app:prefs:v1`, extended JSON: `categoryTargets`, `namePattern`, `advanced`, `qualityPreset` added alongside `lang`/`theme`. Loading validates and merges — v1-era stored prefs (`{lang, theme}` only) load fine.
- Changing a queue item's target `<select>` records `categoryTargets[category]`; `makeItem`/add-files uses the remembered default when it is a valid target for the category, else `defaultTarget` from detect.ts. The armed quick-route (Feature 1) takes precedence over the remembered default.

### 3 — Batch rename
- `naming.ts`: `applyNamePattern(originalName, pattern, {target, index})` with tokens `{name}`, `{ext}`, `{target}` (via `outputExtFor`, so `images → png`, `split → pdf`), `{date}` (local YYYYMMDD), `{n}`. Empty pattern → original name.
- Advanced panel gains the "Output name pattern" input (placeholder `{name}-converted`) + token hint; persisted in prefs.
- Applied to per-item outputs at completion and to bundle names (`merged.pdf`, `images-combined.pdf`, `queued-files.zip`). **Not** applied to extracted ZIP contents (archive category is explicitly skipped).
- Safety nets (documented judgment calls): if the pattern result has no extension, the output's real extension is re-attached (so `{name}-converted` → `photo-converted.jpg`, not an extension-less download); duplicate output names within one item are disambiguated with ` (2)`, ` (3)`…

### 4 — Quality presets
- Segmented control at the top of the Advanced panel: Small file / Balanced / Best quality / Custom, `aria-pressed` states, persisted via prefs.
- Presets write exactly: Small `{quality 60, maxDim 1600, gifFps 10, gifWidth 480}`, Balanced `{80, 2560, 12, 720}`, Best `{95, 0, 15, 1080}`; other fields (resize %, rotate, trim, split) untouched.
- The indicator is **derived**: `matchPreset(advanced)` compares the four controlled fields, so manually editing any of them flips the indicator to Custom (or to another preset on an exact match), and clicking "Custom" itself changes nothing. Fresh installs start on Balanced values; returning users' saved advanced values are never overwritten — since v1 never persisted advanced values, the first v1.1 visit of a v1 user starts from Balanced, and from then on their values persist verbatim.

### 5 — Plain-language errors
- `errors.ts`: `explainError(raw, item, t)` returns a full "what happened + what to try" sentence, all wording from new i18n keys (EN+AR). Mapping order: `SPLIT_RANGE_MISSING` (existing key, text reworded with try-this) → `PDF_PASSWORD` (also any raw message containing "password") → `UNSUPPORTED` → `UNKNOWN_TYPE` → `EMPTY_RESULT` → TOO_BIG (> 200 MB in image/PDF paths) → media (FFmpeg: smaller file / different format / check connection for the one-time engine download) → HEIC heuristic (kept from v1) → generic with try-this.
- PDF password detection: `converters/pdf.ts` wraps pdf.js `getDocument` and pdf-lib `PDFDocument.load` (split + merge); `PasswordException` name or /password|encrypted/i message → `throw new Error('PDF_PASSWORD')`.
- `EMPTY_RESULT`: App throws it when a converter resolves with 0 outputs (e.g. extracting an empty ZIP); converter internals unchanged otherwise.
- `convertAll`'s unknown-type pre-check now also routes through `explainError`.

### 6 — Share target (⚠ not device-verifiable here)
- Manifest: `share_target` `{action: "/share-target", method: "POST", enctype: "multipart/form-data", params.files[0] = {name: "files", accept: [image/*, video/*, audio/*, application/pdf, application/zip, text/*, .csv, .xlsx]}}`. Verified in `dist/manifest.webmanifest` (parses, share_target present, everything else unchanged).
- `public/sw.js`: cache `converter-app-v3`. The fetch handler checks `POST` + pathname `/share-target` **first**: parses formData, stores each file into IndexedDB (`converter-share` v1 / `inbox`, `{name, type, blob, ts}`, auto-increment) using an inline plain-JS copy of the IDB code, then `Response.redirect('/?shared=1', 303)`; any failure → `'/?shared=0'`. Non-share POSTs and cross-origin requests are not intercepted; GET cache-first logic unchanged.
- `src/lib/shareInbox.ts`: `takeSharedFiles()` opens the same DB, reads all entries, clears the store, returns `File` objects. On mount, App drains the inbox → `addFiles`, announces via the live region, and strips the `?shared` param with `history.replaceState`.
- **Unverified:** the full loop (Android share sheet → SW POST → inbox → queue) needs a real Android device/TWA or Chrome with an installed PWA; it cannot be exercised in this environment. The redirect also depends on the SW controlling the page, i.e. the app must have been visited at least once before sharing works.

## Quirk fixes

- **(a) Clear all** now runs `setItems([])` **and** `setBundles([])`. Removing items one-by-one still leaves bundles in place (intentional — bundles are separate results).
- **(b) Category-aware target labels:** `targetLabel(t, category, target)` in `i18n.ts` — `html` → "HTML page" / «صفحة HTML» for text, "HTML table" / «جدول HTML» for data; all other targets use the existing map. Used by the queue `<select>` options and quick chips.
- **(c) Advanced panel strictly user-controlled — CONFIRMED BY CODE INSPECTION.** `grep` over `src/` shows exactly three touchpoints for `advOpen`/`setAdvOpen`: the `useState(false)` initialiser, the toggle button's `onClick`, and the render/`aria-expanded` reads. Nothing in the add-files flow (drop/pick/paste/share), conversion flow, or effects touches it, and it is not persisted anywhere.

## Quality passes

1. **Mobile first:** quick chips and the segmented control wrap (`flex-wrap`); at ≤ 560 px the advanced grid is forced to a single column and segment buttons go two-per-row; the rename field spans the full grid width. New UI verified against the 360–420 px layout rules in CSS (no fixed widths that can overflow).

Verified present in `dist/index.html`. Header/main landmarks unchanged.
