# Converter App v1.2 — "Cinematic Layers" (design-only stage)

Built on top of v1.1. **No conversion-engine changes** (`src/lib/converters/*` and `src/lib/detect.ts` untouched — verified by file timestamps), **no behaviour changes** to any v1.1 feature (queue, quick chips, advanced, presets, rename, share inbox, errors). All work is in `src/styles.css`, the drop-zone markup/handlers and empty state in `src/App.tsx`, plus the service-worker cache bump. `npm run build` passes clean (tsc strict + vite); no new dependencies.

## What was added, per element

### 1. Tangerine aurora field
- New `<div className="aurora" aria-hidden="true">` as the first child of `.app`; `.app` gets `position: relative; z-index: 1` so content paints above it.
- The aurora is `position: fixed` (top −24vh, centred, 130vw × 74vh, max-width 1600px) so it can never create scrollable overflow; `html, body { overflow-x: clip }` added as a safeguard. `pointer-events: none`.
- Three layered radial gradients (tangerine `--aurora-a`, deep orange `--aurora-b`, amber `--aurora-c`) at different positions/sizes, `filter: blur(56px) saturate(1.25)`, one slow drift: `aurora-drift` 34s ease-in-out infinite alternate, **transform/opacity-only keyframes** (small translateX/translateY + scale 1→1.06 around the centred position).
- Theme handling: gradient stops and overall opacity are CSS variables. Dark: rich stops (α .50/.42/.32), opacity .8. Light: paler stops (α .30/.24/.28), opacity .5 — a soft pastel wash.

### 2. Glass cards
- `.card` (Quick convert, Advanced, Queue, Bundles) inside `@supports ((backdrop-filter: blur(14px)) or (-webkit-backdrop-filter: …))`: translucent theme-aware `--glass-bg` (dark rgba(18,22,31,.74), light rgba(255,255,255,.78)), `backdrop-filter: blur(14px) saturate(1.3)`, 1px `--glass-border` (white α .09 dark / ink α .09 light), and layered shadows (`--shadow` ambient + `--shadow-soft` tight).
- Fallback: browsers without backdrop-filter keep the exact v1.1 solid `--surface` card.
- Contrast: glass opacity kept high (.74/.78) so text stays AA over the aurora in both themes; verified by eye against the token pairs (dark text #e8ecf4, light text #1c2331, muted tokens unchanged).

### 3. Drop-zone 3D tilt + shine
- Pointer handlers (`onPointerMove`/`onPointerLeave`) + a rAF loop that lerps current→target rotation (factor 0.14) and writes `perspective(900px) rotateX/rotateY` inline. Max ±4° per axis. The loop parks when settled (no idle rAF spin) and re-kicks on the next move; on leave it eases back to flat and clears the inline transform + `.tilt-on` class.
- Gating: only when `(hover: hover) and (pointer: fine)` matches, pointer is over the zone, no drag is in progress (`dragRef` mirrors the drag state; drag keeps its existing `.drag` emphasis), and `prefers-reduced-motion` does not match. Touch/small screens never tilt.
- Shine: `.dropzone::after` radial gradient positioned by `--mx/--my` custom properties set from the pointer, faded in on hover (hover-capable devices only). The focusable element itself gets **no** `overflow: hidden`, so the focus outline is never clipped.
- Existing `role="button"`, `tabIndex`, Enter/Space handling, click-to-open and drag/drop handlers are byte-for-byte unchanged; the tilt code only adds handlers alongside them. While `.tilt-on` is present, the transform transition is dropped from the transition list so the CSS transition never fights the rAF lerp.

### 4. Primary actions — sheen + lift
- `.primary-btn` and `.dl-btn` get a `::after` sheen (white gradient, skewed −18°) that sweeps across on hover (transform-only, .65s), clipped by `overflow: hidden` on the button (outlines live outside the border box and stay visible).
- Convert-all additionally lifts on hover (translateY(−1px), deeper tangerine shadow 0 12px 26px α .42); `:active` press (scale .98) and the download buttons' `:active` scale (.97) were re-asserted after the hover rules so press feedback still wins. Disabled state unchanged.

### 5. Progress with depth
- Track: inset shadows (`--track-inset` per theme + a faint bottom highlight).
- Bar: three-stop tangerine gradient (#e05f00 → accent → accent-strong), soft outer glow (0 0 10px rgba(242,118,10,.5)), and an internal shine sweep (`bar-shine` 1.6s ease-in-out infinite, transform-only, clipped by the bar's own `overflow: hidden` + the track's).
- ARIA progressbar attributes from v1.1 untouched.

### 6. Premium empty state
- The bare paragraph is now an `.empty-state` block: an inline, `aria-hidden` SVG (140×96) in the app's own visual language — two layered floating file cards (back card muted/surface-2, front card surface with tangerine stroke, abstract line details, accent dot) with a circular tangerine badge carrying the brand's double-arrow conversion mark in white. All colours via CSS variables/current tokens, so it follows the theme.
- Gentle `floaty` animation (translateY −5px, 5–7.5s, staggered delays, `transform-box: fill-box`). The existing i18n empty-queue string is kept verbatim beneath the art. No emoji, no external images.

## Passes
- **Mobile first:** aurora sized in vw/vh and centred; backdrop-filter applied only to the four `.card` surfaces; empty art caps at 60vw; tilt/shine are inert on touch. Render smoke-tested headlessly (aurora, empty art, drop-zone role, live region all present in the DOM).
- **Accessibility:** decorative layers are `aria-hidden` + `pointer-events: none`; `:focus-visible` rules untouched and kept visible above the glass; text tokens unchanged over high-opacity glass (AA). Reduced motion: global v1.1 rule already collapses animations/transitions; v1.2 additionally sets `.aurora { animation: none }`, hides the progress shine, stops the float, removes hover lift, and the tilt JS refuses to run under `prefers-reduced-motion`.
- **SEO:** index.html untouched, as specified.
- **Keyboard:** tab order and all v1.1 keyboard support untouched; no traps introduced; tilt transform never clips the drop-zone focus outline (shine is a pseudo-layer, no overflow hidden on the focusable element).
- **RTL:** no new physical left/right positioning except the centred aurora (`left: 50%` + translate, symmetric) and the buttons' sheen origin (purely cosmetic sweep direction); tilt/shine follow the pointer, so Arabic layout is unaffected.

## Housekeeping
- `public/sw.js`: `CACHE_NAME` bumped `converter-app-v3` → `converter-app-v4` (only change; dist verified to carry v4). Share-target handling untouched.

## Risk notes
- `backdrop-filter` over a `position: fixed` aurora requires the aurora to be in the cards' backdrop — implemented via sibling stacking (aurora z-index 0, `.app` z-index 1); verified pattern in Chromium; the `@supports` fallback keeps unsupported browsers on the v1.1 solid cards.
- Backdrop blur is GPU-costly on very low-end phones; it is limited to the few cards and the aurora is a single blurred fixed layer (blur applied once to the layer, not per-card).
- The tilt writes inline `transform` on the drop-zone; the pre-existing `.drag` scale(1.01) can be overridden by a stale tilt angle during a drag — tilt input is paused while dragging, and pointer-leave eases it flat, so the effect is momentary and cosmetic only.
